# M1: Hook, clock, overlay shell

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5); reviewer: maintainer
- Status: done (maintainer approved moving on; manual checklist not yet confirmed)

## What was built
- `loupe/core/clock.lua`: pause, fixed-size single steps, speed presets (0.1x to 4x).
- `loupe/core/hook.lua`: wraps callbacks through a metatable, so games that reassign
  `love.update` at runtime stay wrapped (ADR 0004).
- `loupe/init.lua`: `attach(opts)`, `detach()`, `isAttached()`, `isOpen()`, `setOpen()`.
  Configurable keys; does nothing in headless runs.
- `loupe/panels/statusbar.lua`: placeholder time-control bar that emits draw commands.
  A compact badge stays visible when the overlay is hidden but time is altered.
- `loupe/ui/render_love.lua`: the only drawing code. Resets origin, scissor and canvas so the
  overlay ignores the game's camera.
- `examples/asteroids` attaches loupe. Smoke runs open the overlay so the real renderer is exercised.

## Test-first evidence
`spec/core/clock_spec.lua` and `spec/core/hook_spec.lua` were written first and failed on the
missing modules (27 specs once green). `spec/loupe_attach_spec.lua` was written before `attach`
existed and failed on `detach` being nil. Totals: 40 specs; `core/` coverage 100%.

## Verification beyond unit tests
- `love examples/asteroids --smoke 120` exits 0 with the overlay drawn every frame.
- A throwaway LÖVE script (kept outside the repo) paused a moving ball at frame 20 and captured a
  screenshot at frame 40. The ball had stopped, and the bar drew in screen space despite a game-side
  `translate`.

## Design calls made by the AI (for review)
- **Pause skips the game's update instead of passing dt = 0.** Asteroids fires bullets inside
  `update` when the cooldown is 0, so a zero-dt "pause" would keep firing.
- Steps ignore the speed scale, so a step is always exactly `stepSize`.
- Time keys only work while the overlay is open; F1 always works.

## What the gates caught
Nothing this milestone. StyLua, luacheck and the tests were green on the first full run. (Not a
claim that the code is bug-free: see known limitations.)

## Known limitations
- When loupe consumes a key (e.g. F1), the game still receives the matching `keyreleased` and
  `textinput` events. Harmless for the example; revisit when M2 adds text fields.
- The status bar has a fixed width rather than measuring text; M2's layout replaces it.
- CI workflows exist but never run, because the project is local-only by maintainer decision.
  `tools/check.sh` is the gate of record.

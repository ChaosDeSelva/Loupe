# 1.0 integration (lead agent)

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5), lead agent; reviewer: maintainer
- Status: done; tagged `v1.0.0` locally. Manual checklists not yet confirmed by the maintainer.

## What happened
The maintainer asked for every remaining milestone at once, taken to 1.0, using subagents in
parallel. The lead:
1. finished M5 itself, because it was mid-change in `init.lua`, the file most likely to conflict;
2. made the first local commit, since worktrees need one to branch from;
3. ran three agents in separate worktrees with disjoint file scopes: M6 hot reload (the only one
   allowed to touch `init.lua`), the 1.0 polish pass (`ui/`, panels, picker, geometry), and the
   docs (no code). The docs agent wrote against a fixed hot-reload API contract;
4. merged the branches (docs, then polish, then M6) without conflicts, then integrated and
   verified the result.

"Push to 1.0" was taken as "bring to version 1.0". The project stays local: no remote, no push.

## Integration work
- Wired `selection.stale` (`reflect.resolve` follows the selection's keys from its root).
- Key repeat turns on only while a loupe field has focus, and the game's setting is restored after
  (also when the overlay closes mid-edit, and on `detach`).
- "unsaved changes" moved next to the Save button, so it no longer hides the latest message.
- A hot reload that fails while the overlay is hidden shows in the corner badge until the overlay
  is next opened.
- `_VERSION = "1.0.0"`; fixed the `loupe.ui` header example; checked that the rockspec's 26
  modules match the files on disk.
- Docs reconciled with the built behavior: `api.md`, `CHANGELOG.md`, `docs/AI.md`, roadmap,
  manual checklist, case study.

## Numbers
330 specs (up from 323 after merging). Coverage: `core/` 99.7%, `ui/` 99.6%. 0 luacheck warnings
across 63 files. Library 3,068 lines; specs 3,872 lines (all Lua under `loupe/` and `spec/`).

## What the gates and checks caught
1. **The gates broke because of the worktrees.** luacheck and StyLua scanned the agents' worktree
   copies under `.claude/`. Fixed by excluding `.claude/` in `.luacheckrc` and `.styluaignore`.
2. **A shipped bug from M4: Inspector edits to world-picked objects were never saved.** Found by a
   new integration spec while wiring the stale flag. The world-pick path dropped `root`/`keys`
   from the selection. Fixed, with a spec covering pick, then edit, then save.
3. **The lead's own test sequencing mistake.** Press and move were sent in one frame, so the press
   was hit-tested at the moved position. The spec was fixed, not the code.
4. "Restores key repeat if the overlay closes mid-edit" **passed vacuously** before the feature
   existed. It became meaningful once repeat was turned on.

## Test-first evidence
The integration specs (stale, unsaved label, key repeat, badge alert, `reflect.resolve`) were
written first: 4 failures and 1 error before the code. The world-pick save spec failed before its
one-line fix.

## Verified in real LÖVE (one process at a time)
- Hot reload in a scratch copy of asteroids: an edit recolored the ship live; a syntax error was
  reported and the game kept running on the last good code.
- Text cursor in the gallery: Left, Left, `X` gave "Fjord rangXer".
- Leaf nodes without arrows; all three examples pass `--smoke`.

## Known limitations at 1.0
See `CHANGELOG.md` and `docs/api.md`: `keyreleased` and `love.mouse.isDown` still see input loupe
used; there's no text selection or clipboard; overrides keyed by array index follow the index;
hot reload doesn't patch file-scope locals; the suite has run on LuaJIT only, never plain Lua
5.1; click-to-cycle and culling are verified by specs only.

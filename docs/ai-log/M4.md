# M4: In-world selection

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5); reviewer: maintainer
- Status: done (maintainer approved moving on; manual checklist not yet confirmed)

## What was built
- `loupe/core/geometry.lua`:
  - `bounds` uses a fallback chain: user hook, `w/h`, `width/height`, `r/radius`, `def.*`,
    then a point marker. There's an optional center anchor.
  - `collect` finds positioned tables under the roots, with paths. It's cycle-safe, limited to
    6 levels deep and 5,000 objects, and respects a `pickable` filter.
  - `pick` chooses the smallest box under the point.
- `loupe/core/picker.lua`: hover, press to select, drag in world units through
  `toWorld`/`toScreen`, a 3px drag threshold, drags that continue across windows, and outline
  and path-label commands in screen space. The label goes below the box when there's no room
  above.
- The toolbar has a Pick on/off switch. `attach` takes `pick`, `toWorld`, `toScreen`, `bounds`,
  `center`, `pickable` (ADR 0006).
- `examples/platformer`: a 640x360 virtual resolution letterboxed into a resizable window, a
  following camera, a string scene state machine, AABB physics, coins, enemies, and a flag. It
  passes its view transforms and excludes the camera from picking.

## Test-first evidence
`geometry_spec` and `picker_spec` failed on missing modules first. The world-picking attach
specs had 2 failures before `init.lua` changed. Two of the four new attach specs (the "Pick
off" cases) passed before the change, because clicks still went to the game. They only became
meaningful once picking existed. That's noted here rather than claimed as red-first.

## What the gates and checks caught
1. **Another assertion that couldn't fail (caught by the AI on reread, before running).**
   `assert.equal(4, list[1].h or 4)` passes even when `h` is nil. It's the same mistake as M3's
   color test. Replaced with an exact check of the player's box.
2. **A crashing test hook exposed an API contract (caught by a spec error).** The picker spec's
   `bounds` hook indexed `o.pos` on every table, including `pos` itself. Real hooks see every
   table under the roots too. The contract ("return nil for tables you don't recognize") is now
   documented in `geometry.lua`, `init.lua` and ADR 0006, and the spec follows it.
3. A `require` left inside `picker:frame` was moved to the top of the file before review.

## Design calls made by the AI (for review)
- **Pick is on by default**, so while the overlay is open the game gets no clicks at all.
  That's right for an editor, but surprising in mouse-driven games, where you'd switch it off.
- **Smallest box wins** among overlapping hits. The alternative, "drawn on top", isn't knowable
  without hooking the game's draw order.
- **Without a `bounds` hook, `w/h` boxes are treated as top-left.** Games using centered boxes
  pass `center = true`; radius-based objects are always centered.

## Known limitations
- No "click again to cycle" through stacked objects of equal size.
- Rotation isn't modeled: boxes are axis-aligned, and the transforms must map points only.
- A moving object fights a drag while the game is running, because the game keeps writing its
  position. Pausing first avoids it.
- Collection walks the watched tree every frame while Pick is on. It's capped at 5,000 objects,
  but untested on very large games.

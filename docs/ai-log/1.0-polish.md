# 1.0 polish: UI and picking limitations

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5), one of three parallel agents (hot reload and docs ran
  separately); reviewer: maintainer
- Status: done in unit tests; not yet run in real LÖVE (this agent was told not to launch it
  while other agents were running)

## What was built
Fixes for five "Known limitations" from M2–M4, in priority order:

1. **Leaf nodes in Objects (M3).** `ui:treeNode` takes `opts.leaf`: no arrow, never opens,
   never touches the stored open state, and with `selectable` the whole row picks (including
   where the arrow would be). The label is shifted by the width of `"> "` so it lines up with
   siblings. `panels/objects.lua` marks a node as a leaf when it holds no tables (colors
   don't count, because the tree doesn't list them). The Inspector also draws empty nested
   tables (`{}`) as leaves.
2. **Text cursor (M2).** `textField` and typed `dragNumber` editing keep a byte-offset cursor.
   Left/right, home/end, backspace and delete work at the cursor, and typed text is inserted
   there. `ui/utf8.lua` gained `prev(text, pos)` and `next(text, pos)`, which step over whole
   UTF-8 characters. The caret is a 1px rect where the cursor is (it used to be a `|`
   appended to the text). The view keeps a scroll start that moves only as far as needed to
   keep the cursor visible, and moves back when the text shrinks, so typing at the end still
   keeps the end visible. A click inside the field while editing places the cursor at the
   nearest character boundary.
3. **Click-to-cycle stacked objects (M4).** `geometry.hits(list, x, y)` returns every box
   under the point, smallest first (equal areas ordered by path, so the order doesn't depend
   on `pairs`). `geometry.pick` is `hits(...)[1]`. In `core/picker.lua`, a press picks the
   smallest box, or the box picked last time if the press is within 3px of the last pick.
   **Releasing** that press without dragging advances to the next larger box, wrapping
   around. Cycling on release rather than on press means you can press on an object you
   cycled to and drag it. A drag that wanders off and comes back isn't treated as a click.
   A press on empty space resets the cycle.
4. **Off-screen rows (M2).** `Context:place` marks the box as culled when it lies entirely
   outside the window's content area, and `Context:emit` drops commands while culled. Layout
   still advances, so content height and scrolling are unchanged. Window chrome, `unclip` and
   the scrollbar are emitted with culling off. Auto-height windows never cull (see "caught" 1).
5. **Stale selection (M3).** `inspector:build` shows a dim "(no longer in the game)" row under
   the path when `selection.stale` is true. Setting `stale` is left to `init.lua` (the lead).

Public signatures are unchanged: `objects.build(ui, roots, selection, rect)`,
`inspector:build(ui, selection, rect, edit)`, `picker:frame(input, free, list, view, set)`,
`picker.highlight(...)`, `geometry.pick(list, x, y)`.

## Test-first evidence
Each spec was run red before its implementation:
- Leaf nodes: widgets + objects specs gave 5 failures and 1 error (`picked` was nil when the
  arrow zone of a leaf was clicked). The new "draws an arrow that shows whether it's open"
  spec passed from the start: it pins down the existing behavior.
- Inspector: empty-table leaf and stale note gave 2 failures.
- Cursor: utf8 specs gave 2 errors (`prev`/`next` missing); widget specs gave 13 failures
  (cursor movement, caret position, no `|` in the text, click-to-place, long-text scrolling,
  typed `dragNumber` at the cursor).
- Cycling: geometry gave 3 errors (`hits` missing); picker gave 4 failures and 1 error. "Starts
  over after a click on empty space" passed before the change, because the old picker always
  started over.
- Culling: 3 failures in context specs. "Still count toward the content height" passed before
  the change, as intended: it's a guard that culling doesn't change layout.
- Two specs were written after the code. I then checked that each fails when its fix is
  reverted:
  - "doesn't cycle when a drag comes back to where it started" failed with the `press.moved`
    check removed.
  - "draws every row of an auto-height window" failed with the auto-height guard removed.

## What the gates and checks caught
1. **A regression from culling, caught by `loupe_attach_spec`.** The toolbar is an auto-height
   window. On its first frame it still has its initial small height, so its status row
   ("1 saved override no longer matches…") was culled and two attach specs failed. Fixed by
   never culling in auto-height windows; there's a spec for it now.
2. **Existing specs that relied on drawing everything.** The "caps very long tables" specs
   (Objects and Inspector) looked for the "... N more" row, which is now off-screen. They
   scroll to the bottom first now. The context scroll spec used
   `findText(cmds, "row 1")`, a plain substring search that also matches "row 10" to
   "row 19". It now uses a new exact-match helper, `driver.findExact`, on a row that is
   actually in view.
3. **A wrong index in my own spec.** The stale-note color check read `cmd[6]`, but text
   commands carry color at index 5. It failed (got nil), so the assertion could fail, and I
   fixed the index.
4. **Weak-assertion check.** "(no longer in the game)" doesn't appear in the window title or
   path. The "live selection" spec checks that the note is absent. The leaf specs compare
   the whole drawn string (`"ship  {1}"` vs `"> rocks  {2}"`) rather than a substring.
   The caret is found as the only 1px-wide rect.

## Known limitations
- No text selection, clipboard, or word-wise movement (Ctrl+arrows). The caret doesn't blink.
- Arrow/backspace auto-repeat depends on LÖVE's key repeat. loupe doesn't turn on
  `love.keyboard.setKeyRepeat` (that would be `init.lua`), so holding left moves once.
- Cycling remembers the last object it picked, not the Inspector's current selection. If you
  pick something else in Objects and then click the same world spot, the cycle continues
  from the old pick.
- The hover outline always shows the smallest box under the pointer, not the one the next
  click would cycle to.
- Culling is per row. A single row taller than the view is still emitted whole (none exist
  today).
- Stale detection itself isn't here; only the display is.

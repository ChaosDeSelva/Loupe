# 1.1.1: finishing the UI (one-line text, clean drags, selection and clipboard, key releases)

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5); reviewer: maintainer
- Status: done, awaiting maintainer review (ran next to an agent fixing Lua 5.1 portability in
  the examples; this work didn't touch `core/` or the game examples)

## What was built
1. **Multi-line and control-character strings show on one row.** New `ui/escape.lua` (pure):
   `oneLine(str, glyphs)` for display, and `encode`/`decode` for editing, where
   `decode(encode(s)) == s`. The context has `ctx:oneLine(str)` and `ctx.glyphs`
   (`{ newline, tab }`; empty means `\n`/`\t` written out). `fitText`, `fitTextStart`, the window
   header count, every widget label and every text command go through it. Text is escaped before
   it's measured, so truncation fits what's drawn. `render_love` escapes text commands too, as
   a backstop for text built outside the UI. `init.lua` escapes the picker's path pill, because
   `core/picker` measures that text itself. `syncTheme` uses "↵" and "→" only when both the body
   and the mono font have the glyph (checked with `hasGlyphs`, like the ellipsis).
   **Editing design:** a string that contains control characters is edited in its escaped form
   (`a\nb` shows as `a`, `\`, `n`, `b`) and decoded on commit. Its newlines survive an edit that
   doesn't touch them, and typing `\n` adds one. A string without control characters edits
   exactly as typed, with no change from 1.1: a backslash stays a backslash. Pasting text that
   has control characters switches the edit to the escaped form, keeping the cursor and the
   selection on the same characters. I chose this over read-only because multi-line strings
   (dialogue, notes) are the ones people want to fix live. It's documented above the editing
   code in `ui/widgets.lua`.
2. **Clean drag values.** A dragged value is rounded to one decimal place finer than the step
   per pixel (`ceil(-log10(step)) + 1`, between 0 and 6 places). Shift's finer step gets one
   more place. Typed values are never rounded.
3. **Selection and clipboard in `textField` and in a `dragNumber` being typed into.**
   - Shift with Left, Right, Home or End extends the selection.
   - Left and Right collapse a selection to its edge.
   - Ctrl/Cmd+A selects all.
   - Typing, Backspace and Delete replace the selection.
   - Ctrl/Cmd+C, X and V copy, cut and paste. Copying from an escaped edit copies the real
     characters.
   - The selection is highlighted with the new theme color `selectionText`.
   - Everything works on UTF-8 boundaries.
   - Each key event in the input snapshot now carries the modifiers held when it was pressed
     (`{ key, shift, ctrl }`); `input:keypressed(key, mods)` takes them. The clipboard is
     injected with `ui.new({ clipboard = { get, set } })`. Without one, a context keeps its own
     clipboard. `init.lua` wires `love.system.getClipboardText`/`setClipboardText`.
   - Ctrl/Cmd+Z, Y and S are still checked before a focused field gets the key. A, C, X and V
     fall through to the field with the rest of the typing.
4. **Key releases no longer leak.** `keypressed` records which keys (by key and scancode) loupe
   used, and the matching `keyreleased` is swallowed once. The latest press of a key decides,
   and releases of keys the game got still reach it. A hotkey loupe used while not typing
   (for example `p` while open) also swallows the next `textinput`, which in LÖVE arrives right
   after the press. The flag clears on the next `update`, so a later, unrelated character still
   gets through. Leaking that text was a real bug: `p` and `]` produce text input in LÖVE.
- `examples/ui_gallery` wires the clipboard and modifiers, sets the arrow glyph when the font
  has it, and shows a multi-line `note` field.

## What the checks caught
1. My first LÖVE script pressed `p` to test hotkey swallowing. That paused the game, so the
   script, which ran in `love.update`, never reached its quit. The bug was in the script, not
   in loupe. Fixed by pressing `p` twice.
2. `render_love` caches fonts across specs, so the "font has the arrow" attach spec first
   picked up an earlier spec's font. That spec now reloads `render_love` and `loupe`, and
   reloads them again in `finally`.
3. `math.log10` is gone in Lua 5.2+. 5.1 and LuaJIT have it, but I switched to
   `math.log(x) / math.log(10)` anyway.

## Remaining limitations
- **Saved files still show float noise.** `core/serialize.lua` writes non-integers with
  `%.17g`, so the clean 0.05 is saved as `0.050000000000000003`. The live value is right. The
  fix belongs in core (out of scope here): write the shortest of `%.15g`/`%.16g`/`%.17g` that
  reads back equal.
- The bundled font subsets lack "↵" (and the mono subset lacks "→"). Re-subsetting with
  U+21B5 and U+2192 would turn the arrows on; the code already checks.
- Shown (not edited) text doesn't escape backslashes, so a literal `a\nb` and a real
  newline look the same until edited. The edit shows the exact form.
- No mouse drag-selection, Shift+click, word jumps or in-field undo. Ctrl/Cmd+Z still undoes
  loupe edits, not the field's text, as in 1.1.
- `love.keyboard.isDown` and `love.mouse.isDown` still report keys and buttons loupe consumed.
  A game that polls them can react; only callbacks are filtered.
- Swallowing hotkey text is a heuristic: the first `textinput` after a used non-typing press,
  until the next update.

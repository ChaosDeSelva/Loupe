# M6: Hot reload

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5); reviewer: maintainer
- Status: implemented on a branch; awaiting real-LÖVE verification and review

## What was built
- `core/hotswap.lua` (pure Lua): `patch(old, new, previous, shared)` merges a reloaded module
  into the live table in place. Functions are always replaced; tables in both are patched
  recursively with identity kept; references to new tables (including `Class.__index = Class`)
  are remapped to their old counterparts; cycles are safe. Plain values are taken from the file
  only if the file changed them relative to `previous`, and keys are removed only if the
  previous version defined them, so runtime state survives. `shared` tables (other modules) are
  never patched. Also `snapshot(value, shared)` and `reloadable(loaded, ignore)`, which skips
  `loupe`, `loupe.*`, `main`, `conf` and user patterns. Rules are in ADR 0007.
- `loupe/reload.lua`: a watcher that checks at most every 0.5 s of real time. It maps
  `a.b` to `a/b.lua` or `a/b/init.lua` through `love.filesystem.getInfo`, tracks `modtime`, and
  on an increase runs `love.filesystem.load` and the chunk inside `pcall`, then patches.
  Results are `{ name, ok, err? }`. Modules are baselined when it starts and when they first
  appear after a lazy `require`.
- `init.lua`: `attach({ hotReload, reloadIgnore })`. Checks run in the `update` wrapper with
  the real dt, so they work while paused. Messages: `reloaded <name>`, `reloaded N modules`,
  `reload failed: <name>: <err>` (warning). Every result is also printed with a `loupe: `
  prefix. Default on only when `storage.sourceFolder()` finds a folder (newly exported).
- `spec/support/love_stub.lua`: `fake.modtimes` feeds `getInfo().modtime`, and
  `love.filesystem.load` mimics LÖVE 11.5 (nil + message for a missing file, throws
  `Syntax error: ...\n` on bad syntax). Existing behavior is unchanged.

## Numbers
281 specs (up from 230). Coverage: `core/` 99.66%, `ui/` 99.54%; `hotswap.lua` and
`reload.lua` both 100%. 0 luacheck warnings across 62 files.

## Test-first evidence
- First run with only the specs written: `hotswap_spec` and `reload_spec` errored on missing
  modules, and 6 of the 10 new attach specs failed. The other 4 (ignore patterns, disabled,
  default off, headless) assert that nothing happens, so they passed before any code existed;
  they guard against regressions rather than drive the design.
- The `shared` rule (below) was added test-first too: 4 new hotswap specs failed before it.

## What the gates and checks caught
1. **A data-corruption risk (caught by the AI rereading its first hotswap draft).** Recursive
   patching paired tables by key. If a module had `M.level = require("levels.one")` and the
   game later set `M.level = require("levels.two")`, a reload would have overwritten
   `levels.two`'s contents with `levels.one`'s. Fixed with the `shared` set: every table in
   `package.loaded` is treated as an opaque value. Snapshots keep shared tables by reference,
   so the game's repointing also survives when the file didn't change that line.
2. **Missed remapping inside new tables (caught while writing a spec).** A table only the new
   version has (`new.states.idle.owner = new`) was adopted as is, leaving a reference to the
   discarded new root. New tables are now walked and remapped too. The first fix still skipped
   their nested tables (the "same table in both" check fired because old and new were the same
   table); the spec caught it before commit.
3. **luacheck W212.** `M:reload` never used `self`; it became a local function.
4. **StyLua** reflowed one long assertion in `reload_spec.lua`.

## Deviations from the brief
- `hotswap.patch` takes two optional extra arguments, `previous` and `shared`. `patch(old, new)`
  behaves exactly as specified (the simple rule). The brief's recommended "previous version"
  rule is what `reload.lua` uses.
- `reloadable(loaded, ignore)` takes a `package.loaded`-shaped table and returns sorted names,
  rather than judging one name at a time.
- Successful reloads are printed as well as failures.
- Only LuaJIT is installed locally; Lua 5.1 runs in CI. The code uses only 5.1 APIs
  (`loadstring`, `pcall` with arguments, no `goto`).
- LÖVE was not launched (other agents share the machine); real-LÖVE checks are left to the
  maintainer.

## Known limitations
- File-scope locals and upvalues aren't patched; old closures keep old upvalues. Top-level
  side effects run again on reload.
- The status message only shows while the overlay is open, and "unsaved changes" takes
  precedence over it. A failed reload with the overlay closed is visible only in the console.
- The first baseline is taken at `attach`, so runtime changes made before then are treated as
  file values.
- Metatables of reloaded modules are not updated.

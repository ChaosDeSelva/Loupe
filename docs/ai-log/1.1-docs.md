## How it was checked
Every claim was read against the code, not the logs: `loupe/init.lua` (the `guard` boundary,
`handleKey` order, `warnUnsaved`, `currentRoot`), `core/hook.lua`, `core/overrides.lua`
(`persistable`, `path`, `parse`), `core/geometry.lua` (the three caps), `core/serialize.lua`,
`storage.lua` (`writeReplacing`, `parse`), `reload.lua` (`candidates`), and the example sources
for every field path listed in the changelog and README. Field paths were also diffed against
the 1.0 examples (`git show 5fe5742:...`) so only new tunables are listed as new. LÖVE wasn't
launched. `stylua --check .` and `luacheck .` were run to confirm no code changed.

## Doc/code mismatches found
Fixed in these docs:
1. `docs/api.md` said the overrides file "runs with an empty environment, so it can only build
   data". That's the overstatement ADR 0003 now corrects. Replaced with the ADR's wording:
   bytecode refused, empty environment, instruction limit; string methods reachable, memory not
   limited.
2. `docs/api.md` said every key goes to a focused text field. Since 1.1, Ctrl/Cmd+Z/Y/S are
   checked first (`handleKey`), so the routing table and Keys section were wrong.
3. `docs/api.md` said override keys are "strings or numbers". The code (`persistable`) requires
   finite numbers, and refuses boolean keys on both save and load.
4. `docs/api.md`'s `ctx:textField` row said "Editing happens at the end of the text only". The
   field has had a UTF-8 cursor with Left/Right, Home/End and Delete since 1.0 polish (and the
   same file's Watching section already said so). Fixed in that one row.
5. `docs/api.md` described the world walk with two caps; the code has a third, `MAX_VISITS`.
6. `docs/api.md` didn't mention that a patch failure during hot reload is also a "reload
   failed", or how module files are located.
7. `docs/manual-test.md` M0: the ship's invulnerability is 2.5 s (`spawnShield`), not 2, and a
   rock costs one of 3 lives instead of ending the game. The game now opens on a title screen
   (Enter starts), WASD also steers, and a new wave comes after a pause and a banner.
8. `docs/manual-test.md` M3: Objects now also lists `fx` and `sound`; `bullets` has `radius`
   and `color`; the HUD score counts up rather than jumping to a typed value.
9. `docs/manual-test.md` M4: `game.spawn` is a new pickable `x, y` marker, so it's added to the
   hover line.
10. `README.md`'s examples table described the 1.0 games (no fullscreen keys, no controls, no
    new roots).

Left for the lead (outside this task's scope, or in `.lua` files I may not touch):
11. **`loupe._VERSION` is still `"1.0.0"`** (`loupe/init.lua:23`), and the rockspec is
    `loupe-1.0.0-1.rockspec` with `tag = "v1.0.0"`. The changelog's 1.1.0 entry notes this
    under Known limitations; bump both when tagging.
12. `ctx:treeNode` accepts an undocumented `opts.leaf` (`loupe/ui/widgets.lua:309`), used by the
    Objects window. Not added to `api.md`, because the UI redesign may change the toolkit.
13. `docs/AI.md` lists "Runs in real LÖVE ... by the lead agent" as a gate. Neither 1.1 branch
    was run in LÖVE (both logs say so), so that gate is still open for 1.1.
14. The brief said the world-picked Inspector-save fix belonged in 1.1. It was fixed in the
    1.0 integration commit (`a9c8547`) before 1.0.0 was tagged, so 1.0.0 never shipped with
    it. It's not listed in 1.1.0.
15. The brief said the two 1.1 logs contain manual-test lines. They don't have a checklist; I
    wrote the 1.1 checklist items from their "what was fixed", "what was not verified" and
    "remaining limitations" sections, and from the code.
16. The changelog's 1.0.0 entry still says the overrides file "is loaded as data only". It's
    left as written (it's history); the 1.1.0 Security section corrects it.

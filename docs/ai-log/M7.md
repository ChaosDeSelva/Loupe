## What was built
- `docs/api.md`: reference for `loupe.attach` and every option, `detach`, `isAttached`,
  `isOpen`, `setOpen`, `watch`/`unwatch`, `_VERSION`; default keys and the Ctrl/Cmd shortcuts;
  input routing per event; world-picking rules; undo/redo; the `loupe_overrides.lua` format,
  location and loading rules; hot reload; headless behavior; and the standalone `loupe.ui`
  toolkit (context, input, windows, widgets, renderer, draw commands).
- `README.md` rewritten for 1.0: pitch, install, three-line quick start, features, a
  camera/letterbox snippet taken from `examples/platformer`, key table, examples, the AI process
  section, development, license.
- `CHANGELOG.md` (Keep a Changelog) with the 1.0.0 entry.
- `loupe-1.0.0-1.rockspec`: builtin build mapping all 24 current `loupe/**/*.lua` files, plus
  `loupe.core.hotswap` and `loupe.reload`, which the M6 branch adds.
- `docs/case-study.md`: a draft built only from the M0–M5 logs, the ADRs and git history.

## How the docs were checked
- Every option, default, key and message string in `api.md` and the README was read off the
  source (`loupe/init.lua`, `storage.lua`, `core/overrides.lua`, `core/geometry.lua`,
  `core/clock.lua`, `core/registry.lua`, `core/history.lua`, `panels/toolbar.lua`, `ui/*.lua`),
  not from earlier docs. The quick start and camera snippet are copies of code in the examples.
- `luarocks lint loupe-1.0.0-1.rockspec` passes. A LuaJIT script loaded the rockspec and checked
  each module path exists: 24 of 26 do; the two missing are the M6 files, as expected.
- `stylua --check .` and `luacheck .` are clean (0 warnings / 0 errors in 58 files): no Lua was
  touched. LÖVE was not launched (out of scope for a docs-only change), and busted was not run
  for the same reason.

## Not verified
- **Hot reload is documented from a contract, not from code.** `hotReload`, `reloadIgnore`, the
  never-reloaded modules and the two toolbar messages follow the contract given for M6. The
  implementation wasn't visible on this branch. Details the docs assert beyond the contract and
  that need checking against M6: that hot reload does nothing while detached or headless, and
  that a reloaded file's top-level code runs again (which follows from "re-run").
- The case study's tally and patterns are the AI's own categorization of its own logs.

## Inconsistencies found (reported, not fixed: `.lua` files were out of scope)
1. `loupe._VERSION` is `"0.0.0"` in `loupe/init.lua`; the release is 1.0.0.
2. `loupe/ui/init.lua`'s header example passes `measure = font.getWidth`. `getWidth` is a method,
   so that call would receive the text as `self` and fail; it should be
   `function(t) return font:getWidth(t) end` or `render.measure`. `api.md` uses `render.measure`.
3. The README before this change said "Clicks and typing aimed at loupe never reach your game".
   The game still receives `keyreleased` for consumed keys (M1/M2 known limitation), and while
   Pick is on, all mouse buttons are captured, not only the one loupe uses. `api.md` states both.
4. `docs/AI.md` lists CI as a place each gate runs and the real-LÖVE smoke as "CI" only; CI has
   never run. It also says the logs feed the case study "at v0.1"; the release is 1.0.
5. `docs/roadmap.md` is still titled "Roadmap to v0.1" (left for the lead, as instructed).
6. ADR 0003 says "We'll document this in M5" about array-index overrides; it is now documented in
   `api.md`.

# 1.1 hardening: fixes from the 1.0 code review

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5), working in an isolated worktree while another agent redesigned
  the UI; reviewer: maintainer
- Status: done, pending review and merge with the UI redesign

## What was fixed
- **C1, chaining a love callback after attach overflowed the stack** (`core/hook.lua`). This is
  the `hump.gamestate.registerEvents()` pattern: it runs from `love.load`, after `attach`, and
  calls the `old` it captured, which is loupe's wrapper. `__newindex` now records
  `prev[fn]`, what `fn` replaced, the first time `fn` is assigned. The wrapper tracks which game
  function in the chain is running. A call back into the wrapper while one is running goes
  straight to `prev[running]` without loupe's logic. This works for chains of any depth, for a
  chain that ends in "nothing", and after `detach`, where the stale wrapper passes through to the
  game's chain. Assigning the wrapper to itself is ignored. ADR 0004 now describes the rule and
  its limits.
- **C2, an edit through a non-string/number key crashed the host** (`overrides.entryId` →
  `serialize` threw on function, table and userdata keys). The new `overrides.persistable(keys)`
  accepts only strings and finite numbers, and it replaces `validKeys`, so saving and loading use
  the same rule. Boolean keys used to save but were dropped on load; now they're refused on both
  sides. `overrides:record` returns false instead of throwing. `edits:set` applies the edit,
  keeps undo working, skips saving, and returns false. init shows "can't save <path>: it's
  reached through a key that isn't a string or number". The new `overrides.path(root, keys)` is
  the old private `pathOf`.
- **I1, no error boundary.** init.lua has one `guard(fn)` that wraps `drawOverlay` (draw),
  `applyOverrides` and the hot-reload poll (update) in `xpcall` with a traceback. On an error it
  prints `loupe: <error + traceback>` once (it doesn't repeat until F1 reopens the overlay),
  closes the overlay, sets the badge alert "loupe hit an error (see console) - F1 to reopen", and
  the game's own callback still runs that frame. If the hot-reload poll fails, hot reload turns
  off so it doesn't fail again every half second. The boundary also **rebuilds the UI context,
  inspector and picker**. See "what the specs caught" #2 for why.
  Supporting fixes:
  - `reflect.fields` and `keyLabel` survive a key whose `__tostring` throws or returns a
    non-string. Each name is worked out once before sorting, not on every comparison.
  - `reload.lua` runs `hotswap.patch` under `pcall`, so a locked module table gives a normal
    "reload failed" result.
- **I3, per-frame costs in `geometry.collect`.** There's a new `MAX_VISITS` (20000), counted
  across all roots, that caps the tables visited. `MAX_OBJECTS` still caps the result. The walk
  no longer allocates a path string and a key list for every table it visits. It keeps one
  shared key stack, copies it only for tables that become entries, and builds `entry.path` on
  first read through an `__index` metatable (then caches it). `entry.path`, `.root` and `.keys`
  work as before for picker and init.
- **I4, the overrides "sandbox" accepted bytecode.** `storage.parse` now refuses text starting
  with `\27`. It runs the chunk under a count hook (`MAX_INSTRUCTIONS` = 1e6) and puts back any
  previous hook afterwards. ADR 0003 now says what this does and doesn't guarantee: string
  methods are reachable and memory isn't limited.
- Minor fixes:
  - `storage.write` writes `loupe_overrides.lua.tmp`, checks the `write` and `close` results,
    then renames it over the target. If that fails it removes the old file and retries, because
    Windows won't rename over an existing file. Failures are reported.
  - `serialize` writes integers with `%.0f` instead of `%d`. `%d` goes through a C `long`,
    which is 32 bits on 64-bit Windows. Zero is special-cased so the output stays `0`, not `-0`.
  - Ctrl/Cmd+S/Z/Y now work while a loupe text field has focus. They're checked before the
    field gets the key. Saving doesn't commit the field.
  - `reload.lua` finds module files through `love.filesystem.getRequirePath()`, then falls back
    to LÖVE's defaults. `love_stub` gained `getRequirePath`.
  - Undo/redo follow a getter's replaced root. `edits.new({ resolveRoot })` records the root's
    table on each change. Before undoing or redoing, a change whose root has since changed is
    pointed at the same keys under the new root. If that field doesn't exist there, it keeps the
    old target. `history` gained `peekUndo`/`peekRedo`.
  - Spec noise: `loupe_attach_spec` stubs `print` for every test, so busted's output is just
    the dots.

## Test-first evidence
Each spec was written and run before the code it covers:
- hook: 5 errors (stack overflow / table overflow; the run took 47s while the stack filled).
  Two passed before the fix ("chain set up before install", "plain scene switch"). That was
  expected: they guard behaviour the fix must keep.
- overrides + edits: 7 failures, 4 errors. One was the actual crash (`serialize.lua:28: can't
  write a function`), and `persistable`/`path` didn't exist yet.
- attach (init): 10 failures, 1 error. The bounds hook, toWorld, strict `__newindex`, strict
  `__index`, `__tostring` and override-apply errors all propagated out of `love.draw` or
  `love.update`. The C2 message and the getter-root undo were missing. Ctrl+S with a focused
  field didn't save. The C2 attach spec no longer crashed because the core fix had already
  landed, so it was red only on the missing message.
- reflect: 1 error (`tostring broke`).
- geometry: 3 failures, 1 error. The visit cap didn't exist and `path` was built eagerly. "Every
  entry gets its own key list" passed before the change, as a guard for the new shared key stack.
- storage: bytecode was accepted, and the read-only-folder write *succeeded* (the old code
  opened the existing, still-writable file in place). The infinite-loop spec hung busted, and I
  killed it.
- reload: require-path lookup failed, and the patch error propagated (`module is locked`).
- serialize: **passed before the fix** on this machine. macOS has a 64-bit `long`, so `%d` is
  exact here, and I can't make it fail on this platform. It stays as a regression guard for
  Windows.
- The attach-level hump `registerEvents` spec was written after the hook fix, so I never saw it
  red. The hook specs cover the same bug red.

## What the gates and specs caught
1. **LuaJIT ignores count hooks in compiled code.** The first instruction limit didn't work:
   `while true do end` got JIT-compiled and the spec hung. Fixed with `jit.off(chunk, true)`
   before running the file. Without the spec, the "can't hang the game" claim would have been
   false on LÖVE's own runtime.
2. **An error inside a window would break loupe permanently.** `ui/context.lua` asserts
   `not self.win` in `beginWindow`. An error thrown between `beginWindow` and `endWindow` leaves
   `self.win` set, so after F1 every frame would fail again. A spec makes `objects.build` throw
   once, mid-window, then reopens and draws. The boundary now rebuilds `state.ui`,
   `state.inspector` and `state.picker`. Window positions reset after an error, which is
   acceptable.
3. **Test bugs in my own specs.**
   - "read-only" in a `string.find` pattern: `-` is a pattern character, so the assertion
     failed even though the code worked. Switched to plain find.
   - After the top-level `print` stub went in, a spec that used `print` as a "function key" was
     using the stub, which is a callable table. It failed in the suite but passed alone. Switched
     to a local function.
   - A focused-field spec asserted before the frame that commits the field.
4. luacheck caught a new helper (`rootValue`) shadowing a local in `markStale`. Renamed it to
   `currentRoot` rather than touch `markStale`.

## Not changed, and why
- **NaN areas in `geometry.hits` sorting.** I didn't change this, because the case can't
  happen. `contains()` runs before the sort and rejects every box with a NaN coordinate or size.
  Even `w = inf, h = 0`, the one way to get a NaN area from numbers, fails `y < y + 0`. So no
  NaN area reaches `table.sort`. An attach-level spec (a bounds hook returning NaNs, then hover
  and click) passed before and after. Making the comparator NaN-proof would add code that no
  test can reach. If the maintainer wants it anyway, it's one line in `before()`.

## Remaining limitations
- If a game callback throws through the wrapper, the chain's "running" marker isn't reset. This
  only matters to a custom `love.run` that catches errors and keeps going (ADR 0004). loupe
  doesn't `pcall` the game's callbacks because that would spoil the game author's traceback.
- A chaining function's `prev` is fixed at its first assignment.
- The error boundary covers draw and update work. Input callbacks (`keypressed`,
  `mousepressed`, ...) only run loupe's own UI routing and aren't guarded.
- Rebuilding the UI after an error loses window positions and the open/closed state of tree
  nodes.
- The overrides loader doesn't limit memory (`("x"):rep(1e9)`), as ADR 0003 now says.
- The write-failure, rename-fallback and `close`-failure branches in `storage.write` aren't
  exercised: macOS can't easily simulate them, and the Windows fallback can't run here.
- The serialize fix can't be shown red on a platform where `long` is 64 bits.
- The Ctrl+S-while-typing spec clicks Inspector rows by pixel position, like the existing
  integration specs. It will need new coordinates after the UI redesign.
- LÖVE wasn't launched for this work (another agent was using it). Only specs verify these
  fixes, so a smoke run is still owed.

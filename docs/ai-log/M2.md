# M2: Immediate-mode UI toolkit

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5); reviewer: maintainer
- Status: done (maintainer approved moving on; manual checklist not yet confirmed)

## What was built
- `loupe/ui/`, all pure Lua except the renderer:
  - `input.lua`: buffers events between frames; typing kept in arrival order.
  - `layout.lua`: vertical stack, `sameLine`, indentation.
  - `context.lua`: windows (drag by title, z-order, wheel scroll with scrollbar, auto height),
    ids with `pushId`/`popId` and `"label##id"`, hot/active tracking, hit-testing against last
    frame's windows, `wantsMouse`/`wantsKeyboard`.
  - `widgets.lua`: label, separator, button, checkbox, dragNumber (drag, or click to type;
    min/max/integer), textField (UTF-8-safe backspace), treeNode/treePop, colorSwatch.
  - `utf8.lua`, `theme.lua`, `init.lua` (`ui.new`, `ui.newInput`).
  - `render_love.lua`: adds outlines, clipping, and loupe's own font.
- `loupe/panels/toolbar.lua`: the M1 status bar became a real draggable window with buttons.
  `panels/badge.lua` keeps the corner badge for when the overlay is hidden.
- `loupe/init.lua` routes input: clicks and wheel over loupe windows stay out of the game;
  releases always reach the UI; while a loupe field is focused, keys and text go to the field
  and the time hotkeys are off (closes the M1 "typing 1 resets speed" gap).
- `examples/ui_gallery`: every widget, using `loupe.ui` without the rest of loupe.

## Test-first evidence
- `context_spec` and `widgets_spec` were written before `context.lua`/`widgets.lua` and failed
  on the missing module.
- The input-routing specs in `loupe_attach_spec` were written before the new `init.lua`.
- **Deviation:** `input_spec` and `layout_spec` were written in the same step as their
  modules, so they were never seen failing first.

## What the gates and checks caught
1. **A garbled expression (caught by the AI rereading it, before any run).** The first draft of
   the widget fill-color helper had a meaningless middle clause
   (`hovered and c.widget == nil and c.widget`). It was rewritten as a plain if/elseif.
2. **Typing order bug (caught by a spec).** Within one frame, all typed text was applied
   before any keys, so "backspace, backspace, 3" on "10" produced "1" instead of "3".
   Input now records text and keys in one ordered list. The now-redundant `text`/`keys`
   fields were then removed so there is one source of truth.
3. **Clicks landing in the wrong place (caught only in real LÖVE).** The overlay polled
   `love.mouse.getPosition()` each frame, overwriting the position the click happened at.
   All unit tests passed because the attach spec moved the fake mouse to the click point,
   which masked the bug. Scripted clicks in a real LÖVE run all missed. Fixed by taking
   position from events only (ADR 0005). The spec no longer moves the fake mouse, so it now
   guards against this.
4. A circular require between `context.lua` and `widgets.lua` was avoided by design before
   running: the UTF-8 helper moved to its own module.
5. **An overclaim in the log (caught by the AI on reread).** M1's log was first marked
   "reviewed by maintainer" when the maintainer had only said to move on. Corrected to say
   the manual checklist isn't confirmed.

## Verification beyond unit tests
A scratch harness (outside the repo) ran both examples in real LÖVE with scripted input, then
captured screenshots:
- Gallery: tree node opened, text field edited with a typed "!", scroll window wheel-scrolled
  to row 06.
- Asteroids: F1 opened the window and clicking Pause paused the game (button became Resume,
  label PAUSED).

Both examples also pass `--smoke 90`.

## Known limitations
- Text fields edit at the end only (no cursor movement, selection, or clipboard).
- No window resizing; scrollbars are display-only (wheel to scroll).
- Rows scrolled out of view are still emitted, then clipped. That's fine at inspector scale;
  revisit if M3 shows thousands of rows.
- Clicks loupe keeps from the game don't hide the button from `love.mouse.isDown`, so a game
  that polls the mouse can still see it.
- The game still gets `keyreleased` for keys loupe consumed.

# M3: Registry and inspector

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5); reviewer: maintainer
- Status: done (maintainer approved moving on; manual checklist not yet confirmed)

## What was built
- `loupe/core/registry.lua`: named watched roots. A root may be a getter function, resolved every
  frame, so `game = newGame()` stays watched. A getter that throws is reported in the panel
  instead of crashing the game's draw.
- `loupe/core/reflect.lua`: value kinds (including `{r,g,b[,a]}` colors in 0..1), ordered field
  lists (array part, then numbers, strings, others), Lua-style key labels and paths
  (`game.rocks[3]`, `t["two words"]`, keywords quoted), and short summaries (table size,
  LÖVE userdata via `:type()`).
- `ui` `treeNode` gained `selectable`/`selected`: the arrow toggles, the label picks.
- `loupe/panels/objects.lua`: tree of roots and their child tables, with cycle markers and a
  cap of 200 children per node.
- `loupe/panels/inspector.lua`: editors for the selected table (drag/type numbers, checkboxes,
  text fields, expandable colors, inline nested tables), cycle markers, cap of 200 fields.
- `loupe.watch(target, name)` / `loupe.unwatch(name)`, usable before `attach` and headless.
- `examples/asteroids` watches `game` (getter), `rockSizes` (shared defs), and `bullets`.

## Test-first evidence
Every new module's spec was written and run red first: registry, reflect, the selectable tree
node (3 failures before the change), both panels (module not found), and the attach/watch
integration (1 failure, 3 errors before `init.lua` changed).

## What the gates and checks caught
1. **A false positive in a color check (caught by the AI rereading it).** `isColor` accepted
   `{[2]=1, [3]=1, [4]=1}` because it only checked the count and `t[n]`. A failing case was
   added to the spec first, then the check was tightened to require keys 1..n.
2. **A test that couldn't fail (caught by the AI before running).** The inspector's color test
   asserted that the text "r" appeared after expanding, but the window title "Inspector"
   already contains an "r". The channels were renamed red/green/blue/alpha and the test now
   asserts that "green" is absent before and present after.
3. **luacheck W431.** A local `step` in the new tree-node specs shadowed the outer `step`.
   Renamed. The zero-warning gate stopped the run until it was fixed.
4. **A clumsy double scan.** The first draft of the Objects panel walked a table's fields a
   second time just to count hidden children. Rewritten to collect child tables once.

## Verification beyond unit tests
A scripted real-LÖVE run (scratch harness, outside the repo) of asteroids pressed F1, clicked
`ship` in Objects, and dragged `thrust` in the Inspector. The screenshot shows `game.ship`
selected and highlighted, every ship field listed, and thrust moved from 220 to 286 while the
game ran. This is M3's "done when" condition. Both examples pass `--smoke 90`.

## Design calls made by the AI (for review)
- Getter roots are the recommended way to watch game state, because games commonly replace
  their state table on restart.
- Tree and field ids come from keys, not displayed text, so open state survives counts changing.
- Numbers drag as floats even when currently whole. Inferring "integer" from 0 or 220 would lock
  fields like `angle` to whole numbers.
- The selection holds the table itself, not a path. It follows an object when an array shifts,
  but after a restart it still points at the old table until you click again.

## Known limitations
- Tables with no child tables still show an expand arrow in Objects (e.g. the `bullets` root).
- Fields are listed with `pairs`; values inherited through `__index` (class methods/defaults)
  aren't shown.
- No way yet to add or delete fields, or to edit keys.
- Selection doesn't notice when its table leaves the game (e.g. a destroyed rock stays shown).

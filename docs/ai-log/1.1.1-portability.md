# 1.1.1 portability: PUC Lua 5.1 and Linux CI, run for real

- Date: 2026-10-09
- Author: Claude Code (Opus 5.5), working in an isolated worktree while another agent edited
  `loupe/ui/**`, `loupe/panels/**` and `loupe/init.lua`; reviewer: maintainer
- Status: done, pending review

Until now the project claimed "runs on Lua 5.1 as well as LuaJIT" and had a CI workflow, but
neither plain PUC Lua 5.1 nor the workflow had ever run. Only LuaJIT on macOS had. This
milestone ran both.

## PUC Lua 5.1 on macOS
- Built from the official tarball into a scratch prefix; nothing installed system-wide and
  `~/.luarocks` untouched:
  - `curl -O https://www.lua.org/ftp/lua-5.1.5.tar.gz`, SHA-256
    `2640fc56a795f29d28ef15e13c34a47e223960b0240e8cb0a82d9b0738695333` (the published hash)
  - `make macosx && make install INSTALL_TOP=<scratch>/prefix` → `Lua 5.1.5`
  - `luarocks --lua-version=5.1 --lua-dir=<prefix> --tree=<scratch>/tree install busted` (and
    `luacov`): busted 2.3.0, luacov 0.17.0, luasystem 0.7.1, luafilesystem 1.9.0, penlight 1.15.0
  - Ran `<tree>/bin/busted --coverage` (its wrapper execs the 5.1 binary) with the
    `luarocks path` environment, then `luacov` and `<prefix>/bin/lua tools/coverage_gate.lua`.
- **Result: 495/495 specs passed on the first run; coverage gate ok (core 99.46%, ui 99.64%).**
  No 5.1 fix was needed, so there's no red-then-green 5.1 spec to record. A grep for LuaJIT-only
  and 5.2+ constructs (`bit`, `jit.*`, `table.new`, `goto`, `\z`/`\x` escapes, `load` with
  env, `table.unpack`, `utf8.*` stdlib, `math.log(x, b)`, `string.pack`, `ffi`) found only
  `storage.lua`'s `jit.off`. That call is already guarded (`rawget(_G, "jit")`), and `utf8` is
  loupe's own module. After the serialize change below: 497/497.

## What running it caught
1. **The smoke loop would have hung CI.** `for game in examples/*/` includes `examples/shared/`.
   That folder is a library with no `main.lua`, so LÖVE sits on its no-game screen forever.
   Verified: `timeout 30 xvfb-run -a love examples/shared/ --smoke 120` exited 124 (killed). The loop
   now skips folders without `main.lua`, every launch is wrapped in `timeout 120`, and both jobs
   have `timeout-minutes: 15`.
2. **Audio was never actually exercised.** With only `SDL_AUDIODRIVER=dummy`, LÖVE printed ALSA
   errors and "Could not open device.", because LÖVE plays sound through OpenAL Soft, not SDL.
   The games still exited 0, because they cope with no audio device, but the sfx code wasn't
   running. `ALSOFT_DRIVERS=null` gives OpenAL a null device. With it the message is gone and all
   three examples still exit 0. I added it to ci.yml.
3. **Every pinned action runs on Node 20**, which GitHub is retiring: checkout@v4, gh-actions-lua@v11,
   gh-actions-luarocks@v5, stylua-action@v4. I bumped them to the Node 24 majors
   (`checkout@v6`, `gh-actions-lua@v13`, `gh-actions-luarocks@v6`, `stylua-action@v5`). Their
   release notes list no input changes: v13 only changes the *default* Lua to 5.5, and we
   always pass `luaVersion`. I confirmed that `luajit-2.1` is still a valid version, and that the
   action symlinks `lua` → `luajit`, which `LUA=lua ./tools/check.sh` relies on.
4. **`spec/storage_spec.lua` "reports a folder it can't write to" failed as root.** root
   ignores `chmod 555`, so the write succeeds. GitHub runners aren't root, so CI would have
   passed, but the spec lied in any root environment (Docker, some CI images). It now probes the
   folder after the chmod and marks itself `pending` if it's still writable. Verified as root in
   the container: 12 successes, 1 pending. `ci-docker.sh` runs the gates as a non-root `ci`
   user, so they match GitHub.
5. Docker only, not a CI issue: the minimized `ubuntu:24.04` image strips `/usr/share/man`, and
   `love`'s postinst fails (`update-alternatives: error: alternative path
   /usr/share/man/man6/love-11.5.6.gz doesn't exist`). The script deletes
   `/etc/dpkg/dpkg.cfg.d/excludes` first.

## Serialize: shortest round-tripping fractions (requested by the lead mid-task)
Saved overrides showed float noise: `number()` wrote `%.17g`, so a clean `0.05` was saved as
`0.050000000000000003`. It now tries `%.15g`, then `%.16g`, and uses the first that satisfies
`tonumber(s) == v`, falling back to `%.17g`. NaN, ±inf, 0 and integers (`%.0f`) are unchanged.
- TDD: new specs in `spec/core/serialize_spec.lua`: `0.05` → `"0.05"`, `-0.25`, `0.7 + 0.1` →
  `"0.7999999999999999"` (16 digits), `0.1 + 0.2` → `"0.30000000000000004"` (17 digits), and `1/3`
  and `2/3` round-trip. `spec/core/overrides_spec.lua` checks that a rendered `0.05` value contains
  `0.05 }`. Red first on both interpreters (`busted spec/core/serialize_spec.lua
  spec/core/overrides_spec.lua`: 26 successes / 2 failures under LuaJIT and under PUC 5.1, got
  `'0.050000000000000003'`). Then green: `spec/core` 176/176 on both.
- `%.Ng` is C `printf` and `tonumber` is C `strtod` on both interpreters, so the output is the
  same. The final Docker run confirms it on Linux under both.

## Not verified
- The workflow itself has not run on GitHub. There's no remote, and I didn't push. Docker
  reproduces its commands, but not the actions: the actions build LuaJIT 2.1 from the git
  branch and Lua 5.1.5 from source, while the container uses Ubuntu's packages. StyLua comes
  from the same v2.5.2 release either way.
- The amd64 run used Docker Desktop's emulation, not a real x86_64 machine.
- Smoke runs prove the examples start, run 120 frames and quit cleanly. They don't check what
  was drawn or heard.
- `luacheck` still uses `std = "luajit"`, so it wouldn't flag an unguarded `bit.*` or `jit.*`. The
  5.1 CI job would catch that only if a spec runs the code. I didn't change `.luacheckrc`
  because it's outside my scope.
